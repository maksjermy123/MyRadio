# Чек-лист после деплоя

Не автоматические тесты — короткая ручная памятка на 1-2 минуты, которую стоит пройти **после каждого** деплоя `main.py` (или `index.html`/`radio_index.html`, если правки затрагивали и фронтенд). Цель — поймать поломку сразу, а не через день случайных наблюдений.

Реальный повод завести этот файл: однажды декоратор `@app.post("/webhook/bible")` из-за правки "уехал" не к той функции. Код при этом был полностью синтаксически корректным (`ast.parse()` ничего не находил) — просто делал не то. В результате бот вообще не отвечал ни на одно сообщение, и это заметили не сразу.

---

## 1. Сервис вообще запустился?

Render → ваш сервис → **Logs**. Ищите:

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:...
==> Your service is live 🎉
```

Если вместо этого — `Traceback`, `ModuleNotFoundError`, `SyntaxError` — деплой не прошёл, дальше можно не проверять, сразу чинить.

## 2. Оба вебхука отвечают?

Отправьте **любое** сообщение (или `/start`) каждому боту по очереди:

- [ ] `@preoradio_bot` — пришёл обычный ответ?
- [ ] `@mybible_reading_bot` — пришло приветственное сообщение с кнопками?

Если правили именно вебхук/webhook-декораторы — проверьте это первым делом, это самое чувствительное место.

## 3. Админ-панель открывается?

В личке с `@mybible_reading_bot` (где вы админ):

- [ ] `/users` — список открылся, кнопки под сообщением кликабельны?
- [ ] Тап по любому ID открывает детальный экран с планами?

## 4. Мини-апп работает от начала до конца?

- [ ] Открыть мини-апп через приветственное сообщение бота
- [ ] Отметить день прочитанным — стрик обновился?
- [ ] Заглянуть во вкладку «План» в мини-аппе Radio — список планов подтягивается?

## 5. Если правили что-то в Supabase (SQL, новые колонки)

- [ ] Запрос выполнился без ошибок (`Success`, а не `ERROR`)?
- [ ] Проверили `select * from <таблица> limit 5`, что данные выглядят как ожидалось?

---

## Если что-то сломалось

1. Не паниковать — в Render можно **откатить** деплой одной кнопкой: Render → сервис → **Deploys** → у предыдущего успешного деплоя есть кнопка **"Rollback to this deploy"**. Это возвращает предыдущую рабочую версию за секунды, пока разбираетесь, что пошло не так.
2. Скопировать последние ~50 строк логов Render и разобрать вместе — практически все баги в этом проекте находились именно так.
